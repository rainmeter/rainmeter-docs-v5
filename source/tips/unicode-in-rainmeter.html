--- layout: docs permalink: tips/unicode-in-rainmeter/ title: 'Unicode in Rainmeter' ---

Use a Unicode encoding when a skin contains text from different languages. Rainmeter 5.0 supports UTF-8 and UTF-16 LE, but the rules for skin files and Lua scripts differ.

Encoding standards

  • ANSI: A legacy Windows code page. Characters outside ASCII depend on the user's active code page, so the same file may display differently on another computer.
  • UTF-8: A Unicode encoding that can represent text from different languages. A UTF-8 byte order mark (BOM) is the three bytes EF BB BF.
  • UTF-16 LE: A Unicode encoding using little-endian code units. Save these files with a BOM so Rainmeter can identify the encoding.

Skin and include files

Skin .ini and include .inc files may be saved as UTF-8, with or without a BOM, or UTF-16 LE with a BOM. Rainmeter detects the encoding when reading the file. Existing files in an ANSI code page remain supported.

UTF-8 with a BOM is a convenient choice for new Unicode files because it explicitly identifies the encoding. Choose the encoding in your text editor when saving; changing a filename extension does not change the encoding.

The !WriteKeyValue bang preserves the encoding of an existing INI file.

Text files read by Quote

The Quote measure automatically detects UTF-8 and UTF-16 LE text files. For files without a BOM, it tries UTF-8 and falls back to the Windows ANSI code page if the bytes are not valid UTF-8.

WebParser resources

For web resources, CodePage controls decoding. The default CodePage=0 uses UTF-8 for downloaded content. Set a specific code page if the resource uses a different encoding.

For local files read with URL=file://, the default CodePage=0 automatically detects UTF-8 or UTF-16 LE, with an ANSI fallback for files without a BOM. You do not need CodePage=1200 merely because a local file is UTF-16 LE. An explicit CodePage overrides automatic detection.

Unicode Lua scripts

Save a Unicode .lua script as UTF-8 with a BOM or UTF-16 LE with a BOM. The BOM tells Rainmeter to convert strings between Unicode skin values and the UTF-8 strings used inside that script.

A UTF-8 script without a BOM does not select Rainmeter's Unicode script mode. Use a BOM when reading or writing skin text containing non-ASCII characters.

The standard Lua string functions work with bytes. For character-aware operations in a Unicode script, use the Unicode string functions, such as string.uclen and string.ucsub.

Reading and writing external text files

Use SKIN:ReadTextFile and SKIN:WriteTextFile for automatic encoding conversion and skin-relative file paths. ReadTextFile uses a file's BOM when present and otherwise reads UTF-8. WriteTextFile defaults to UTF-8.

For example, save this script with a UTF-8 or UTF-16 LE BOM and put TestIn.txt in the skin folder:

``` lua function Read() local text, errorMessage = SKIN:ReadTextFile('TestIn.txt') if not text then print(errorMessage) return end local firstLine = text:match('[^\n]*') SKIN:Bang('!SetOption', 'MeterUTF8', 'Text', firstLine) SKIN:Bang('!UpdateMeter', 'MeterUTF8') SKIN:Bang('!Redraw') end function Write() local success, errorMessage = SKIN:WriteTextFile('TestOut.txt', 'Бешеные псы и англичане', 'UTF-8') if not success then print(errorMessage) end end ```

Define a String meter named MeterUTF8 in the skin to display the first line returned by Read. The font used by that meter must contain the characters you want to display.

Standard Lua io functions read and write byte strings without Rainmeter's automatic Unicode conversion. If you use them instead, choose the byte encoding yourself and handle any BOM explicitly. A BOM identifies the encoding; it does not convert text bytes into that encoding.
